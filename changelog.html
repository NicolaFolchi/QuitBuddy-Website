Release notes

Changelog

A concise record of user-facing QuitBuddy updates. The first public direct-download release ships as a signed and notarized DMG.

June 2026

QuitBuddy 1.0.7 quit-on-window-close release

Adds an optional way to quit an app by clicking its window's close button, and hardens the test suite.

  • New global setting Quit app when closing its window (Preferences → General): clicking a window's red close button quits the whole app like ⌘Q, with no QuitBuddy prompt.
  • It's a Standard feature; free users see it disabled.
  • Works with standard window controls. Apps with custom or hidden title bars, or full-screen windows, may not respond.
  • Added extensive unit, regression, and component tests around the new behavior and the existing quit modes.
June 2026

QuitBuddy 1.0.6 Preferences sidebar and polish release

Redesigns Preferences with a native macOS sidebar that mirrors menu-bar items, polishes the global mode picker and About page, and improves new-rule defaults.

  • Preferences uses a macOS-style sidebar grouped into Settings and App, so License, Permissions, Tutorial, Updates, Help, and About are reachable even when the menu-bar icon is hidden.
  • Global confirmation method is now a grouped settings list with icon, title, and short explanation per mode.
  • About page redesigned with a centered hero, clean info group, and direct Website / Privacy / Support links.
  • New per-app rules added through Preferences default to Confirm mode.
  • Support link now opens a draft email to quitbuddy.support@gmail.com.
June 2026

QuitBuddy 1.0.5 persistence and Command-Q stability release

Fixes settings persistence in sandboxed direct builds and tightens Command-Q handling.

  • Preferences now persist reliably to ~/.config/quitbuddy/.quitbuddy-config.json.
  • Held or repeated Command-Q is treated as one physical quit intent until the keys are released.
  • QuitBuddy protects itself from accidental quit, while allowing the macOS Input Monitoring restart prompt.
  • Command-, now opens the same Preferences window as the menu bar action.
June 2026

QuitBuddy 1.0.4 visual polish release

Improves quit-mode feedback and onboarding while fixing Preferences update stability.

  • Hold, Double-Press, and Never Quit now show clearer runtime HUD visuals.
  • New users get a more guided feature onboarding walkthrough.
  • Preferences updates avoid SwiftUI publishing during view updates.
June 2026

QuitBuddy 1.0.3 update support release

Uses Sparkle as QuitBuddy's sole in-app updater for direct-download releases.

  • Direct builds use Sparkle-powered update checking and installation.
  • The status menu's update action starts the verified Sparkle update flow.
  • Published a signed appcast at https://getquitbuddy.com/appcast.xml.
June 2026

QuitBuddy 1.0.2 post-launch robustness update

Bug fixes from early direct-release usage across Free and Standard.

  • Free: relaunching QuitBuddy now opens Preferences, even when the menu bar icon is crowded out.
  • Free: onboarding now registers QuitBuddy in Accessibility before opening System Settings, so users only need to enable the toggle.
  • Free: the menu bar item is refreshed on reopen to improve practical visibility.
  • Standard: Confirm no longer swallows unrelated keys while handling Return/Escape.
  • Standard: settings now use ~/.config/quitbuddy, with export still saving wherever you choose.
  • Standard: Hold mode and other protected quits no longer target QuitBuddy itself.
  • Standard: slow-quitting apps like Steam or Zoom get more time before a warning appears.
June 2026

QuitBuddy 1.0 direct release

Initial direct-download release with Free mode and Standard lifetime licensing through Lemon Squeezy.

  • Free mode protects one active app rule.
  • Standard unlocks unlimited per-app quit protection rules.
  • Confirm, Hold, Double-Press, Block, and Allow quit behaviors.
  • Adaptive onboarding for permissions and first protected app setup.
  • Privacy-forward local settings with no analytics SDKs.
Pre-release

Launch preparation

Direct distribution, license activation, onboarding clarity, and the marketing website were prepared before the first signed/notarized public artifact.
